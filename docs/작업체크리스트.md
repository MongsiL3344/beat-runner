### T2 결과 (2026-11-15 완료)
- Player 설정: Company=`Mongs`, Product=`NoiseRun`(사용자 결정. 기존 `beat-runner`에서 변경). API 레벨은 `.NET Standard 2.0` 그대로.
- 빌드: `unity command build run --target StandaloneWindows64 --output-path Builds/Windows/NoiseRun.exe --confirm true` → `build status`로 완료 확인. 결과 Succeeded, 오류 0, 경고 1, 약 1분.
- 경고 1개: `System.Windows.Forms.dll assembly is referenced by user code, but is not supported on current platform`. SFB Windows 구현 때문이다. Windows에서 선택창이 실패하면 명세 3.1대로 API Compatibility Level을 `.NET Framework`로 바꿔 다시 빌드하고, 그래도 안 되면 Windows에서도 `F` Songs 대안을 쓴다.
- 산출물: `Builds/Windows/`(`NoiseRun.exe`, `NoiseRun_Data/`, `UnityPlayer.dll`, `MonoBleedingEdge/` 등). 전달용 `Builds/NoiseRun_Windows_T2.zip`(43MB, `NoiseRun/` + `test_audio/` mp3·ogg·wav, `_BackUpThisFolder_ButDontShipItWithYourGame` 폴더는 뺌).
- 빌드 후 맥 Editor 확인: 활성 대상 macOS, 재컴파일 오류·경고 0, PlayMode 테스트 13/13 통과.
- 사람 확인: 사용자 Windows PC가 없어 친구 PC에서 zip 실행. "잘 된다"는 답을 받음(선택창·재생 정상). API 레벨 변경·Songs 대안 전환은 필요 없었다.

### 빌드할 때 주의할 것 (T9·T15)
- **`build run --target StandaloneWindows64`는 활성 대상을 Windows로 바꿔 놓는다(T2에서 확인).** 빌드가 끝나면 반드시 `unity command build.target switch --target StandaloneOSX --confirm true` → `build.target switch_status`로 macOS로 되돌린다. 안 되돌리면 SFB가 맥 Editor에서 Windows 선택창 코드를 탄다(사용자 결정: SFB 원본은 고치지 않는다).
- Product 이름 변경으로 맥 Songs 폴더가 `~/Library/Application Support/Mongs/NoiseRun/Songs/`로 바뀌었다. `테스트 곡 120.wav`를 복사해 뒀다. 예전 `Mongs/beat-runner/Songs/`는 더 이상 안 쓴다.
- 맥 SFB 네이티브 파일은 원본이 Intel 전용이라 arm64+Intel 겸용으로 다시 빌드해 넣었다(`Assets/StandaloneFileBrowser/Plugins/StandaloneFileBrowser.bundle`). (T1)

### 알아 둘 것
- mp3는 Unity가 인코더 앞뒤 빈 구간을 자르지 않아 실제보다 조금 길게 읽힌다(2.000초 → 2.115초). 재생과 분석이 같은 데이터를 쓰므로 박 타이밍은 어긋나지 않는다.
- 개발용 설정 파일은 `Temp/noiserun_dev.txt.off`로 꺼 둔 상태다. 쓸 때 이름을 `noiserun_dev.txt`로 바꾼다. 자동 테스트는 이 파일을 잠시 치웠다가 되돌린다(`DevFileGuard`).
- Songs 폴더(맥): `~/Library/Application Support/Mongs/NoiseRun/Songs/`에 `테스트 곡 120.wav`가 있다.
- 테스트 음원 변환용 ffmpeg는 컨테이너 `/tmp/ff/`에만 있다. 컨테이너가 재시작되면 다시 받아야 한다.
- SSH heredoc 안에서 `unity` 명령을 여러 개 실행할 때는 각 명령에 `</dev/null`을 붙인다. 안 붙이면 첫 명령이 나머지 heredoc을 입력으로 먹어 버린다.
