- **남은 리뷰 항목(제외, 판단 보류)**: M3 dspTime 보간이 명세 6.4 그대로라 시간 진행이 고르지 않아 미세하게 끊길 수 있음(명세 변경 필요, 사람 확인 "프레임 끊김" 답을 보고 결정). L6 노트 시각에 주인공과 장애물이 약 0.1초 겹쳐 보임(x = 시간 × 속도에서 나옴, 싱크 체감 때 함께 봄). L7 곡 끝 뒤 Esc 전까지 Playing에 머묾(T8에서 Escaped). L4 점수 동점 규칙 테스트, L8 피벗 상수 3곳 중복, L9 30분 넘는 곡의 Tiled 타일 수 한도.
- **카메라 줌(사용자 요청 "0.84 줌인, 한 층에 집중")**: 0.84·0.8·0.6·0.5·0.4로 같은 장면을 찍어 비교(`Temp/t5_zoom_grid.png`)했다. 0.84는 위·아래층이 거의 한 층씩 보여 "조금씩만"과 맞지 않았다. 사용자가 **0.5**(1080p 8배 정수 배율), 세로는 복도 한가운데로 골랐다. `GameConfig.CameraZoom`·`PlayCameraOrthoSize`, `CameraDirector.Follow`가 적용한다. 결과 `Temp/t5z_grid.png`. **T7 주의: 주인공 왼쪽으로 보이는 폭이 약 6유닛이라 `ChaserStartDistance` 8·`ChaserMaxDistance` 12가 화면 밖이다. 추격자 거리를 다시 정해야 한다.** 장애물이 화면에 나타나서 닿기까지 약 1.1초(이전 1.9초).
- 사람 확인 요청 중: `autoPlay=true`로 실제 곡을 달려 보며 싱크 체감·프레임 끊김, 난이도별 장애물 양. 답에 따라 `DifficultyNoteRatio*`를 조정하고 T5를 체크한다.

### T5에서 주의할 것 (T4에서 넘겨받은 메모. M1·L6은 T5에서 반영함)
- **(M1) `PixelArt.Make`는 부를 때마다 Texture2D를 새로 만든다.** 복도 타일 수천 개에 타일마다 `Make`하면 텍스처 수천 개 + 배칭 불가. `LevelBuilder.Build`에서 격자당 Sprite를 1개만 만들어 공유하고, `Clear`에서 그 texture·sprite를 Destroy한다(테스트에서 `Bootstrap.Restart` 반복 시 누수 방지).
- **(L6) `SpriteAnimator.Play`를 같은 frames로 다시 부르면 0번 프레임부터 다시 시작한다.** 매 프레임 `Play`를 부르면 달리기가 첫 프레임에 멈춘다. 상태가 바뀔 때만 부른다. 8.3절 잡힘 감속(달리기 프레임 속도 감소)에는 fps 변경 수단이 없으므로 T8에서 `SetFps` 등을 추가하고 명세 4.2에 적는다.
- 피벗: 캐릭터·바닥 장애물·비상구 `(0.5, 0)`, 빨래 `(0.5, 1)`(천장선). 지금 피벗 상수는 `SpriteGallery` 안에만 있다.
- **잡힘 간격 위험**: `ChaserStandOffset` 1.5유닛(24px)은 휘두르기 프레임(몸 반폭 15px) 기준으로 맞췄다. 하지만 `ChaserIdle`·`ChaserRun`은 몸이 더 넓어서(반폭 약 19px + 바닥 자락) 2단계 마주봄(대기 프레임) 동안 **주인공과 몸이 겹친다**(`Temp/t4_swing_check2.png` 첫 칸). T7·T8에서 마주봄 간격을 넓히고 휘두를 때 다가오게 할지, 대기 프레임을 좁힐지 정한다(사용자 결정).
- Editor Game 뷰가 1280×720이면 480×270 기준 2.67배 비정수 배율이라 도트 폭이 2~3px로 들쭉날쭉하다(흐림은 없음). 1920×1080(4배)에서는 생기지 않는다. 문제가 되면 PixelPerfectCamera 등을 검토(사용자 결정 필요).
- 갤러리 다시 보기: `Temp/noiserun_dev.txt`에 `gallery=true` 한 줄 → 플레이 모드 → 캡처. 끝나면 파일을 지운다.

### 빌드할 때 주의할 것 (T9·T15)
- **`build run --target StandaloneWindows64`는 활성 대상을 Windows로 바꿔 놓는다(T2에서 확인).** 빌드가 끝나면 반드시 `unity command build.target switch --target StandaloneOSX --confirm true` → `build.target switch_status`로 macOS로 되돌린다. 안 되돌리면 SFB가 맥 Editor에서 Windows 선택창 코드를 탄다(사용자 결정: SFB 원본은 고치지 않는다).
- Product 이름 변경으로 맥 Songs 폴더가 `~/Library/Application Support/Mongs/NoiseRun/Songs/`로 바뀌었다. `테스트 곡 120.wav`를 복사해 뒀다. 예전 `Mongs/beat-runner/Songs/`는 더 이상 안 쓴다.
- 맥 SFB 네이티브 파일은 원본이 Intel 전용이라 arm64+Intel 겸용으로 다시 빌드해 넣었다(`Assets/StandaloneFileBrowser/Plugins/StandaloneFileBrowser.bundle`). (T1)

### 알아 둘 것
- mp3는 Unity가 인코더 앞뒤 빈 구간을 자르지 않아 실제보다 조금 길게 읽힌다(2.000초 → 2.115초). 재생과 분석이 같은 데이터를 쓰므로 박 타이밍은 어긋나지 않는다.
- 개발용 설정 파일은 `Temp/noiserun_dev.txt.off`로 꺼 둔 상태다. 쓸 때 이름을 `noiserun_dev.txt`로 바꾼다. 자동 테스트는 이 파일을 잠시 치웠다가 되돌린다(`DevFileGuard`).
- Songs 폴더(맥): `~/Library/Application Support/Mongs/NoiseRun/Songs/`에 `테스트 곡 120.wav`가 있다.
- 테스트 음원 변환용 ffmpeg는 컨테이너 `/tmp/ff/`에만 있다. 컨테이너가 재시작되면 다시 받아야 한다.
- SSH heredoc 안에서 `unity` 명령을 여러 개 실행할 때는 각 명령에 `</dev/null`을 붙인다. 안 붙이면 첫 명령이 나머지 heredoc을 입력으로 먹어 버린다.
